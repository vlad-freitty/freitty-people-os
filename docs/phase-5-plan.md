# Фаза 5 — Telegram-бот: план і рішення

21.10.2026 · PRD розділи 3 (Notification), 8 · статус: **виконується без окремого погодження** (див. фаза 2).

## 1. Обсяг і критерій готовності

Прив'язка Telegram-акаунта, нотифікації про нові кроки, прострочення й рішення по заявках, налаштування каналів у
профілі. Плюс in-app канал (дзвіночок і сторінка сповіщень) — PRD 3 має `channel (in_app / telegram)`.
**Готово, коли:** користувач отримує нотифікацію про новий крок протягом 1 хвилини.
Автотест перевіряє весь шлях до виклику Telegram Bot API (з підміненим транспортом); реальну доставку перевіряємо, щойно
буде токен бота (`TELEGRAM_BOT_TOKEN`) — створити бота в @BotFather може лише власник акаунта.

## 2. Схема

```text
Notification   id, recipient_id (User), type, payload, read_at?, channel (in_app/telegram)
               [тех] sent_at?, failed_at?, attempts, error?, created_at
               type: step_assigned / step_overdue / request_done / request_rejected
User           [тех] telegram_chat_id?, telegram_link_code?, telegram_link_expires?, notification_prefs (JSON)
StepInstance   [тех] overdue_notified_at? — щоб прострочення повідомлялося один раз
```

## 3. Рішення

1. **Коли повідомляємо:** крок став активним на людині (зокрема після перепризначення) → `step_assigned`;
   крок прострочено → `step_overdue` виконавцю й керівнику відділу заявки (раз на крок); заявка завершена / відхилена →
   ініціатору (`request_done` / `request_rejected`). Людина без облікового запису User повідомлень не отримує.
2. **Канали:** in-app завжди створюється (якщо тип не вимкнений); Telegram — якщо акаунт прив'язано і тип увімкнено.
   Налаштування — у профілі, окремо для кожного типу й каналу; за замовчуванням усе увімкнено.
3. **Прив'язка:** у профілі кнопка генерує одноразовий код (15 хв) і посилання `t.me/<bot>?start=<код>`; бот на `/start <код>`
   зберігає chat_id. `/stop` у боті або кнопка в профілі — відв'язати.
4. **Доставка:** нотифікації пишуться в тій самій транзакції, що й зміна заявки; воркер кожні 10 с надсилає
   невідправлені Telegram-сповіщення (до 5 спроб, потім `failed_at`). Найгірша затримка — ~10 с, тобто в межах хвилини.
5. **Отримання апдейтів бота:** long polling у воркері (працює без публічної адреси, локально й на staging); якщо задано
   `TELEGRAM_WEBHOOK_SECRET`, можна ввімкнути webhook `/api/telegram/webhook` з перевіркою секретного заголовка.
6. **Прострочення** — воркер раз на 5 хвилин.
7. **Мова повідомлення** — мова профілю отримувача; посилання на заявку будується з `AUTH_URL`.
