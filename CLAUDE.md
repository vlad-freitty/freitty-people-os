## Money map (phase 3)

- `services/shifts.ts` — shifts in local time of the employee's location, `workDate` = start date in that zone,
  confirm, CSV import with preview; locked periods refuse changes.
- `src/server/money/calc.ts` — what a period pays: shifts (hourly/per-shift rate on the work date, ×company coefficient
  on non-working days of the person's calendar), monthly rates pro rata by calendar days, approved bonuses.
- `services/payments.ts` — periods, (re)calculation (keeps adjustments, skips approved/paid), statuses, contractor
  document check, adjustments, lock, monitoring filters, export rows; `money/export.ts` — CSV (BOM) and XLSX.
- Payment line descriptions are language-neutral ("2 × 120.00 USD", "24 h × 7.50 USD/h"); the UI shows the localized kind.

## Calendar & absences map (phase 2)

- `src/server/calendar/core.ts` — a person's layers (company, department chain, location, person), work week,
  non-working dates, `workingDayFn` (used by absence day counts and by request SLA), `countAbsenceDays`.
- `calendar/ics.ts` — ICS parse (import) and build (personal feed `/api/calendar/<token>.ics`).
- `src/server/absences/balance.ts` — periods, accruals, carryover, expiry, FIFO usage; `syncBalance` is idempotent
  (unique `idempotency_key`). `absences/rules.ts` — validation of an absence against its type and policy.
- `services/calendar.ts`, `services/absences.ts` — settings CRUD, calendar view, balance view, adjustments.
- Daily job: `npm run worker` (pg-boss, 00:30 Europe/Kyiv) runs `runDailyBalances`; balances are also synced before
  every booking, so the app is correct even without the worker.

## Request engine map (phase 1)

- `src/server/requests/engine.ts` — start, groups, step actions, reject/return, child requests, reassign, cancel.
  Every transition locks the request row (`SELECT … FOR UPDATE`).
- `requests/assignees.ts` — assignee rules; `requests/kinds.ts` — system actions per kind (start/complete);
  `requests/sla.ts` — working-day SLA in the assignee's time zone (phase 2 plugs calendars into `isWorkingDay`);
  `requests/schema.ts` + `template-schema.ts` — JSON shapes, kind contract, publish validation.
- `services/templates.ts` — constructor (draft → publish, versions); `services/requests.ts` — visibility, cards, «Мої задачі».
- Starter templates 1–4: `src/server/seed/templates.ts` (created only if the code is missing).
- Files: `src/server/storage.ts` (local dir in dev, S3 later), 5-minute HMAC links served by `/api/v1/files/[token]`.
- System roles and their default permissions live in `permissions.ts`; existing databases get changes through a SQL
  data migration generated by `scripts/gen-roles-sql.ts` — never by re-running the seed.

## Architecture rules (PRD 9)

- **All data access goes through `src/server/services/*`.** Every service takes `actor` as the first argument and does
  its own permission checks. ESLint forbids importing Prisma (`@prisma/client` values, `@/server/db`) outside `src/server`.
- Route handlers (`src/app/api/v1/**`) are thin: `route()` in `src/server/http.ts` resolves the actor and maps errors.
  Server components call the same services directly — there is one permission path.
- **Field-level access** lives in `src/server/services/employee-dto.ts`: `basic` (colleague directory) / `full` / `sensitive`.
  A field that is not in the DTO for that level never leaves the server.
- Records outside the actor's visibility return **404**, not 403 (existence is not leaked). Visible-but-not-allowed → 403.
- Every mutation writes `AuditLog` in the same transaction (`src/server/audit.ts`). Audit payloads are redacted for
  readers who lack the data permission (e.g. rate amounts).
- Date-only values travel as `YYYY-MM-DD`, stored as UTC midnight `@db.Date`. Use `src/lib/dates.ts`, never local time.
  Timestamps are shown in the browser time zone (`<LocalTime>`).
- All UI strings via next-intl keys in `messages/{uk,en}.json` (ESLint `i18next/no-literal-string` in `src/app`, `src/components`).
  next-intl treats `.` as nesting, so dotted keys (permission names) are stored as nested objects.
